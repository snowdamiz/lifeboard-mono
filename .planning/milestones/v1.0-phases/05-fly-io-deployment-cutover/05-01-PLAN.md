     apt-get install -y libstdc++6 openssl libncurses5 locales ca-certificates \

`libsqlite3-0` at runtime — without it the app crashes immediately with an ErlangError NIF load
failure. Do NOT add postgresql-client or any other Postgres tooling.

  <name>Task 2: Update fly.toml — remove release_command, add volume mount and DATABASE_PATH</name>
  <files>server/fly.toml</files>
  <action>
Make two targeted changes to server/fly.toml:

1. Remove the entire [deploy] section (both the header and the release_command line):
   ```toml
   [deploy]
     release_command = '/app/bin/migrate'
   ```
   Delete both lines entirely. Do not leave an empty [deploy] section.

2. Add a [mounts] section immediately after [build]:
   ```toml
   [mounts]
     source = "lifeboard_data"
     destination = "/data"
   ```

3. Add DATABASE_PATH to the [env] section:
   ```toml
   [env]
     PHX_HOST = 'mega-planner-api.fly.dev'
     PORT = '4000'
     DATABASE_PATH = '/data/lifeboard.db'
   ```

WHY for release_command removal: The [deploy] release_command runs in an isolated VM that does NOT
have persistent volumes attached. If left in, migrations attempt to run against no database file.

WHY for [mounts]: The Fly volume `lifeboard_data` (to be created in Plan 02) must be declared here
so Fly.io mounts it at /data on each machine boot.

WHY DATABASE_PATH in [env]: `config/runtime.exs` already reads `System.get_env("DATABASE_PATH")`
and uses it as the SQLite file path. Setting it in [env] (not as a secret) is correct — it is not
sensitive. Value MUST be `/data/lifeboard.db` (not `/data/lifeboard_data/lifeboard.db` — the
volume name is NOT a path component).

The resulting fly.toml should have: `[build]`, `[mounts]`, `[env]`, `[http_service]`, `[[vm]]`
sections and NO `[deploy]` section.
  </action>
