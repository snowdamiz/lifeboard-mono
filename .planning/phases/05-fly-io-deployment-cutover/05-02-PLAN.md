<task type="auto">
  <name>Task 1: Create Fly volume and set secrets</name>
  <files></files>
  <action>
Run these Fly CLI commands in order from the server/ directory:

```bash
# 1. Create the persistent volume (1GB is sufficient for the 933KB SQLite file with room to grow)
fly volumes create lifeboard_data --size 1 --region iad --app mega-planner-api

# 2. Set DATABASE_PATH secret (used by config/runtime.exs)
fly secrets set DATABASE_PATH=/data/lifeboard.db --app mega-planner-api

# 3. Remove DATABASE_URL secret (Postgres no longer used; app code does not reference it)
fly secrets unset DATABASE_URL --app mega-planner-api

# 4. Confirm volume exists and secrets are updated
fly volumes list --app mega-planner-api
fly secrets list --app mega-planner-api
```

WHY volume must be created before deploy: fly.toml now declares [mounts] source = "lifeboard_data".
If the volume does not exist at deploy time, Fly.io will fail the deploy with a volume-not-found error.

WHY DATABASE_URL must be unset: The current DATABASE_URL secret points to the PostgreSQL cluster.
Even though application.ex no longer uses it, leaving it set is confusing. config/runtime.exs
reads DATABASE_PATH — DATABASE_URL is dead config.

Expected output from `fly volumes list`: a row showing `lifeboard_data`, region `iad`, 1GB,
attached to `mega-planner-api`.

HANDLING PITFALLS:
- If first `fly deploy` times out waiting for health check: that is OK — the machine is still
  running with the volume attached. Proceed to `fly sftp put`.
- If `fly sftp put` fails with "no instances found": the machine is in a stopped/failed state.
  Run `fly machine start 7815697b2e6ee8 --app mega-planner-api` then retry sftp put.
- If the second `fly deploy` shows migrations running: check `fly logs` — if 0 migrations applied
  that is correct. If migrations fail, the schema_migrations table may be missing; run
  `fly ssh console --app mega-planner-api` then
  `cd /app && bin/mega_planner eval 'MegaPlanner.Release.migrate()'` to debug.
- If `fly ssh console` shows `/data/lifeboard.db` with `0` bytes or read-only errors: run
  `fly ssh console -C "chmod 666 /data/lifeboard.db" --app mega-planner-api` to fix permissions.
