**Replacement block (replaces lines 6-20 exactly):**

```elixir
execute fn ->
  {:ok, %{rows: users}} =
    repo().query("SELECT id, name, email FROM users WHERE household_id IS NULL", [])

  now =
    DateTime.utc_now()
    |> DateTime.truncate(:second)
    |> DateTime.to_iso8601()

  Enum.each(users, fn [user_id, name, email] ->
    household_id = Ecto.UUID.generate()
    household_name = (name || email) <> "'s Household"

    repo().query!(
      "INSERT INTO households (id, name, inserted_at, updated_at) VALUES (?, ?, ?, ?)",
      [household_id, household_name, now, now]
    )

    repo().query!(
      "UPDATE users SET household_id = ? WHERE id = ?",
      [household_id, user_id]
    )
  end)
end
```

**Why each decision:**
- `repo().query/2` (not query!) for SELECT — returns `{:ok, result}` which pattern-matches cleanly
- `repo().query!/2` (with bang) for INSERT/UPDATE — raises on error, which is correct for migration failures
- `now` computed once before the loop — all rows in the batch get the same timestamp (consistent with original NOW() behavior)
- `name || email` — Elixir `||` short-circuits: uses `name` if truthy, falls back to `email` (mirrors COALESCE behavior)
- `"'s Household"` — no escaping needed; Elixir string concatenation, not SQL string interpolation
- Positional params `?` — exqlite/ecto_sqlite3 uses `?` placeholders (not `$1`)
- `user_id` passed back as-is — binary value from SQLite SELECT is passed as positional param without conversion; SQLite handles binary blobs correctly

**Do NOT:**
- Use `$1`, `$2` style positional params — SQLite uses `?`
- Call `Ecto.UUID.dump!/1` on the user_id — pass it through as received from the query
- Add `flush/0` before the `execute fn ->` block — users.household_id already exists from migration 12, no preceding DDL in this migration needs flushing
- Change the comment on line 5 or any other surrounding code
